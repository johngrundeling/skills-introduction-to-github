## Multi-role recommendation, preference & placement

The report no longer produces a single verdict. A **data-driven role catalogue**
(`ROLE_CATALOGUE` in `worker/_bundled_logic.js`) is scored per candidate and
surfaced as a **ranked fit table** on both reports. Roles can be added/renamed in
that one array without touching the scoring logic.

**Roles:** Greeter (welcome, direct & seat) · Floor Usher / Catcher (crowd flow
*and* catching those who fall under prayer) · Head-Usher track · Parking
Assistant · Helper (behind-the-scenes) · Follow-Up Usher · Undergirding (prayer
& giving).

**Fit score** = 40% gifts (Part 3) + 35% temperament (Part 1) + 25% readiness
(Part 2), with gates: safety roles (Floor/Catcher, Head-Usher) are **held** when a
pastoral flag is raised; Ready-only roles are capped to **"grow first"** below
their required readiness band.

**Two selection layers:**
- **Candidate preference** — on their own report: `POST /prefer/<cid>`
  `{roles:[...]}` → stores a `_preference` row + `usher-pref-*` GHL tags.
- **Leadership placement** — on the pastoral report (token-gated dropdown):
  `POST /place/<cid>?token=<PASTORAL_TOKEN>` `{role}` → stores a `_placement`
  row + `usher-placed` and `usher-role-*` GHL tags.

Both `_preference` and `_placement` live in the existing `usher_submission`
table (free-text `section` column) — **no migration required**.

**Build:** the bundled worker is generated by `node worker/build.js`
(`const PAGES = {…}` + `_bundled_logic.js` → `worker.bundled.js`). Run it after
editing any page or the logic, then deploy the rebuilt bundle.
